# Spike report — base prototype

Date: November 10, 2026 · Status: **prototype works on a real Set**
Design: [TDD-v0.2.md](TDD-v0.2.md) · Plan: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) · Evidence: [FORMAT-NOTES.md](FORMAT-NOTES.md)

This is the first working code: the `.als` codec, the canonical explode/implode,
and a semantic diff, validated end-to-end on the real 5.1 MB Live 11.3.43 Set in
`corpus/supreme-something/`. It is a spike, not production.

## What was built

```
cmd/stem/                 CLI: info, check, decompress, explode, implode, diff
internal/als/             .als codec: gunzip/gzip + offset-preserving XML tree
internal/canon/           explode/implode to a SID-addressed canonical directory
internal/diff/            semantic, SID-keyed change list
testdata/small.xml        synthetic fixture (2 tracks + return + master)
```

### Design choices in the code

- **Offset-preserving parser.** `internal/als` parses XML into an element tree
  where every node records its source span. `Element.Raw()` slices the exact
  bytes of any subtree. An unmodified document re-emits byte-for-byte, which is
  the lossless contract (NFR1) and the "preserve unknown XML verbatim" mitigation.
- **Placeholder template.** The canonical form is `document.xml` (the Set with
  each top-level entity replaced by `<!--stem:SID-->`) plus one file per entity.
  Implode splices the raw entity bytes back into the placeholders. Because the
  placeholders occupy the original spans, an unchanged tree reproduces the input
  exactly.
- **SID from Live id.** `SID(kind, liveId, fallback)` hashes the Live numeric Id
  (stable per [FORMAT-NOTES.md](FORMAT-NOTES.md) §2). No merge-time Ids exist; the
  canonical form is where identity lives.
- **Diff by SID.** The diff engine matches entities by SID, so renames, moves and
  edits are reported semantically instead of as blob changes.

## Results

| Check | Result |
| --- | --- |
| Codec round trip (decompress → emit) | **byte-exact** on the real 5,361,806-byte XML |
| Explode → implode | **byte-exact** (21 entities: 12 tracks, 8 returns, 1 master) |
| Canonical fixed point (explode→implode→explode) | **identical** |
| Semantic diff (real Set vs its earlier autosave) | 55+ typed changes, correct add/remove/rename/move/edit |
| Unit + fuzz tests | pass; `go test -fuzz` ran 1.4M inputs with no crash |
| Parse 5.36 MB | ~21 ms (**255 MB/s**) |
| Gunzip 5.36 MB | ~15 ms |

Extrapolated, a 200 MB-of-XML Set parses in ~1.4 s (0.8 s parse + 0.6 s gunzip),
inside NFR2's 5 s budget on this hardware. **Phase 0 experiment E8 answered in
favour of Go's stdlib parser + a hand-rolled scanner.**

## What the spike confirmed or changed

1. **Byte-exact lossless round trip is achievable** with an offset-preserving
   scanner; no float canonicalization is needed to satisfy NFR1. (Reinforces
   CH-A4: never round floats in canonical bytes.)
2. **A real bug taught a real lesson.** The first version derived the master
   track's SID from its byte offset, so the two Sets produced different SIDs and
   the diff reported the master as remove+add. Fixed to key the master on the
   constant `"master"`. This is CH-A7/CH-B3 in miniature: identity must never
   depend on incidental position.
3. **Placeholder canonical form is sound** for this Set. It will need to move
   inside collections (automation lanes, clip slots, rack chains) before merge
   work; right now only top-level entities are detached.
4. **Diff granularity is coarse in places.** Multiple unnamed clips share the
   name `MidiClip`, and device "changed vs replaced" can be ambiguous. Real
   identity for clips/devices needs the same SID treatment as tracks.

## Not done yet (spike scope)

- Only top-level entities are detached; automation, clip slots, scenes and rack
  chains stay inside the template.
- No plugin/blob handling, no asset store, no LFS, no git integration.
- No three-way merge.
- Live acceptance (does Live open the imploded Set?) is unverified — it needs a
  macOS/Windows host (Phase 0 E1–E7).

## Next steps

1. Detach clips, scenes and automation lanes into SID-addressed files.
2. Add an `identity.json` persisted Id→SID map (CH-A7) and a `stem rematch` path.
3. Implement the whole-tree three-way merge over the canonical form (Phase 3),
   proven first by hand in Phase 0 E6.
4. Wire git: explode-on-commit, implode-on-checkout, hidden backup ref (CH-N3).
5. Get the real smoke host for Live acceptance.

## Running it

```
go build -o stem ./cmd/stem
stem info   "corpus/supreme-something/supreme something.als"
stem check  "corpus/supreme-something/supreme something.als"   # byte-exact + fixed point
stem explode "$SET" /tmp/set-canon
stem implode /tmp/set-canon /tmp/rebuilt.als
stem diff   "$SET" "$SET2"
go test ./...
```
